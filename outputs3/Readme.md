# Output Directory

The **outputs** directory stores all intermediate and final results generated during the execution of the Quantum Protein–Ligand Docking framework.

These outputs provide complete traceability of the algorithm, enabling researchers to inspect every stage of the pipeline—from classical preprocessing to the final docking prediction.

The directory is automatically created and populated when the project is executed.

---

# Overview

The generated outputs are grouped into four major categories.

| Directory | Purpose |
|------------|----------|
| project_data.pkl | Stores all preprocessing results |
| circuits | Quantum circuits generated during Grover Search |
| results | Quantum execution results |
| swap_test | SWAP Test circuits and execution results |
| candidate_evaluation | Candidate ranking and final docking report |

---

# project_data.pkl

This file contains all intermediate preprocessing data required for the quantum stages of the algorithm.

It allows notebooks and subsequent phases to reuse preprocessing results without recomputing them.

The serialized object stores

- Protein interaction data
- Ligand interaction data
- Threshold values
- Encoded datasets
- Protein segmentation
- Search patterns
- Amplitude vectors
- Interaction ranges

This file is automatically generated during **Phase 1**.

---

# circuits/

This directory stores the Grover Search circuits generated during **Phase 2**.

Each search iteration has its own folder.

Example

```text
circuits/

├── iteration_1/
├── iteration_2/
├── iteration_3/
└── ...
```

---

## iteration_i/

Each iteration contains

```text
iteration_i/

├── grover.png
├── grover.qpy
├── circuit_info.json
│
├── simulator/
│   ├── transpiled.png
│   └── circuit_info.json
│
└── hardware/
    ├── transpiled.png
    ├── circuit_info.json
    └── job_info.json
```

---

### grover.png

Visualization of the original Grover circuit before transpilation.

---

### grover.qpy

Serialized Qiskit circuit.

Can be reloaded using

```python
from qiskit.qpy import load
```

---

### circuit_info.json

Contains metadata such as

- Number of qubits
- Circuit depth
- Circuit size
- Quantum gate counts

Example

```json
{
    "qubits": 6,
    "depth": 42,
    "size": 78,
    "operations": {
        "h": 6,
        "cx": 18,
        "measure": 6
    }
}
```

---

### simulator/

Contains the transpiled circuit generated for the Aer simulator.

---

### hardware/

Contains the transpiled circuit optimized for the selected IBM Quantum backend.

Additional information includes

- Backend name
- IBM Runtime Job ID
- Circuit statistics after transpilation

---

# results/

Stores measurement results produced during Grover Search.

Example

```text
results/

├── iteration_1/
│   ├── simulator/
│   └── hardware/
│
├── iteration_2/
└── ...
```

---

## simulator/

Contains

```text
simulator/

├── counts.json
├── histogram.png
└── execution_info.json
```

---

### counts.json

Measurement counts returned by the simulator.

Example

```json
{
    "101001": 962,
    "000110": 62
}
```

---

### histogram.png

Measurement histogram for the corresponding Grover Search execution.

---

### execution_info.json

Contains execution metadata

- Backend
- Number of shots
- Circuit depth
- Execution timestamp (optional)

---

## hardware/

Contains the same files as the simulator folder, along with hardware-specific metadata.

---

# candidate_evaluation/

Stores the final outputs of the docking algorithm.

Example

```text
candidate_evaluation/

├── matched_candidates/
│
├── matched_candidates.pkl
│
├── matched_candidates.json
│
├── matched_candidates.txt
│
└── evaluation_report.txt
```

---

## matched_candidates.pkl

Serialized Python object containing all candidates forwarded from the Grover Search stage.

---

## matched_candidates.json

JSON representation of the matched candidates.

Useful for

- debugging
- visualization
- integration with external software

---

## matched_candidates.txt

Human-readable summary of all candidate docking sites.

Includes

- Protein occurrence
- Encoded bit string
- Grover probability

---

## evaluation_report.txt

Final report generated after candidate evaluation.

Contains

- Candidate ranking
- SWAP Test probabilities
- Euclidean distances
- Best docking site
- Matched protein bit string
- Protein interaction sites

---

# Reproducibility

One of the goals of this project is reproducible quantum experiments.

Therefore, every important artifact is preserved, including

- Original circuits
- Transpiled circuits
- Measurement counts
- Histograms
- IBM Runtime Job IDs
- Candidate reports

This enables researchers to reproduce and verify the results without rerunning the complete pipeline.

---

# Notes

- All output directories are created automatically.
- Existing files may be overwritten during subsequent executions.
- The output structure is identical for simulator and IBM Quantum hardware execution whenever applicable.
